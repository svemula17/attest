# Configuration — `attest.toml`

One TOML file says how an installation runs. `attest init` writes it with every knob commented; `attest config` validates it and prints the effective values. It is found at `./attest.toml`, or `--config PATH`, or `$ATTEST_CONFIG`. Every path inside it is relative to the file itself.

Unknown keys in any section are a hard error, so a typo cannot silently disable something.

## The secrets rule

**No secret is ever written in `attest.toml`.** Wherever a credential is needed, the file names the *environment variable* that holds it (`token_env = "OKTA_TOKEN"`) and the process reads `$OKTA_TOKEN` at use time. The parser rejects a source param called `token`, `secret`, `password`, `api_key`, `client_secret` or `secret_access_key`, a literal `[notifications.jira] token`, and a literal `[auth.oidc] client_secret`. The one value that is generated into the file is `[auth] session_secret` — treat the file like a private key (mode `0600`, out of version control).

Environment variables Attest reads directly (not named in the file):

| Variable | Used by |
|---|---|
| `ATTEST_CONFIG` | where `attest.toml` is (alternative to `--config`) |
| `ATTEST_HOST` | `attest serve` bind address (overridden by `--host`) |
| `ATTEST_ADMIN_PASSWORD` | `attest init --admin-email` |
| `ANTHROPIC_API_KEY` | `[llm] enabled = true` |
| `GITHUB_TOKEN`, then `GH_TOKEN` | the `github` collector when `token_env` is not set |
| `ATTEST_API_KEY` | `attest-mcp --config attest.toml` ([mcp.md](mcp.md)) |

## `[server]`

| Key | Default | Meaning |
|---|---|---|
| `host` | `"127.0.0.1"` | bind address |
| `port` | `8765` | bind port |
| `mode` | `"production"` | `"production"` or `"sandbox"` (seeded data, demo users, demo endpoints, anonymous browser = demo engineer) |
| `base_url` | `"http://127.0.0.1:8765"` | the origin browsers use. Drives the session cookie's `Secure` flag (`https://` only), the CSRF origin check, and the OIDC redirect URI `<base_url>/api/auth/oidc/callback`. Behind a proxy set it to the public origin. |

## `[storage]`

| Key | Default | Meaning |
|---|---|---|
| `url` | `"sqlite:///attest.db"` | SQLAlchemy URL. Relative SQLite paths resolve next to the config; `postgresql+psycopg://user:pass@host/db` needs `attest[postgres]`. |

## `[auth]`

| Key | Default | Meaning |
|---|---|---|
| `session_secret` | `""` (generated by `init`) | signs session cookies. Rotating it signs everyone out. |
| `session_hours` | `12` | session cookie lifetime |

### `[auth.oidc]` — sign in with your identity provider

Present = OIDC enabled (Authorization Code + PKCE; ID tokens verified against the issuer's JWKS). `issuer` and `client_id` are required.

| Key | Default | Meaning |
|---|---|---|
| `issuer` | — | e.g. `"https://example.okta.com"`; discovery at `<issuer>/.well-known/openid-configuration` |
| `client_id` | — | the OAuth client |
| `client_secret_env` | `"ATTEST_OIDC_CLIENT_SECRET"` | env var holding the client secret |
| `scopes` | `["openid", "email", "profile"]` | requested scopes |
| `role_claim` | unset | an ID-token claim (e.g. `"groups"`) whose values are mapped through `role_map`; when set, a user's role is re-synced on every sign-in |
| `[auth.oidc.role_map]` | `{}` | claim value → role, e.g. `"attest-admins" = "admin"` |
| `default_role` | `"auditor"` | role for a first-time user with no mapped claim |
| `allowed_domains` | `[]` | e-mail domains allowed to sign in; empty = any |

## `[sources.<id>]`

One block per evidence source. `<id>` is what `attest collect <id>`, `POST /api/sources/<id>/collect` and the run history use.

| Key | Default | Meaning |
|---|---|---|
| `type` | required | `csv`, `json`, `github`, `hris-idp-join`, `aws`, `okta`, `bamboohr`, `http-json` |
| `schedule` | unset (manual only) | 5-field cron, UTC. Invalid expressions fail `attest serve` at startup, naming the source. |
| `enabled` | `true` | `false` keeps the block but never runs it |
| `[sources.<id>.params]` | `{}` | type-specific; see the generated file's comments and [collectors-github-hris-http.md](collectors-github-hris-http.md). Secrets by `*_env` only. |

The default file defines four file-backed sources: `hris` (`imports/hris-roster.csv`), `idp` (`imports/idp-users.csv`), `leavers` (`hris-idp-join`, daily at 06:00 UTC) and `evidence` (`imports/evidence.json`).

## `[[acceptances]]`

A FAIL with a current acceptance passes the CI gate; an expired one fails it. Acceptances can also be created at runtime (`POST /api/acceptances`); both sets count.

| Key | Meaning |
|---|---|
| `control` | control id, e.g. `"CTL-VENDOR-01"` |
| `owner` | who accepted it |
| `reason` | why |
| `expires` | `YYYY-MM-DD` |

## `[sla_overrides]`

`CONTROL-ID = hours` — replaces that control's freshness SLA from the catalog, e.g. `CTL-PEOPLE-01 = 1440`.

## `[llm]`

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `false` | let Claude draft questionnaire answers (`attest[llm]` + `$ANTHROPIC_API_KEY`). The same guardrails validate the output; a hallucinated citation is rejected before a reviewer sees it. |
| `model` | `"claude-opus-5"` | model id |

## `[notifications]`

A new FAIL, a PASS→DEGRADED transition, or a join finding is delivered once per (control, kind, reason) to every enabled target and recorded in the `notifications` table (`GET /api/notifications`).

| Key | Default | Meaning |
|---|---|---|
| `slack_enabled` | `false` | post to an incoming webhook |
| `slack_webhook_env` | `"SLACK_WEBHOOK_URL"` | env var holding the webhook URL |
| `notify_on` | `["FAIL", "finding"]` | any of `FAIL`, `DEGRADED`, `finding` |
| `due_days` | `14` | remediation due date = today + this, shown in Slack and set as the Jira `duedate` |
| `[notifications.owners]` | `{}` | control id → owner (an e-mail, a team name); unlisted controls show `unassigned` |

### `[notifications.jira]`

Present = create a Jira Cloud issue per event (`POST <base_url>/rest/api/3/issue`, basic auth with `email` + the API token).

| Key | Default | Meaning |
|---|---|---|
| `base_url` | `""` | e.g. `"https://example.atlassian.net"` |
| `project` | `""` | project key |
| `email` | `""` | the Atlassian account the token belongs to |
| `token_env` | `"JIRA_TOKEN"` | env var holding the API token |
| `issue_type` | `"Task"` | issue type name |

## `[security]`

| Key | Default | Meaning |
|---|---|---|
| `login_rate_per_minute` | `10` | `POST /api/auth/login` attempts per client IP |
| `api_rate_per_minute` | `600` | every other `/api/*` request per identity (bearer key, else session cookie, else client IP). `0` disables. |
| `allowed_origins` | `[]` | origins besides `server.base_url` that may make cookie-authenticated state changes (a console served from another host) |
| `hsts` | `false` | send `Strict-Transport-Security: max-age=31536000; includeSubDomains`. Only behind TLS. |
| `audit_worm_bucket` | `""` | `s3://bucket/prefix` for the WORM audit export |
| `audit_worm_retain_days` | `365` | Object Lock retention for that export |

Rate limits are per process; see [security.md](security.md) for what that means.

## A complete production example

```toml
[server]
host = "127.0.0.1"                       # nginx in front terminates TLS
port = 8765
mode = "production"
base_url = "https://attest.example.com"

[storage]
url = "postgresql+psycopg://attest:@db.internal:5432/attest"   # password via PGPASSWORD or a .pgpass entry

[auth]
session_secret = "…64 hex chars written by attest init…"
session_hours = 8

[auth.oidc]
issuer = "https://example.okta.com"
client_id = "0oa1example"
client_secret_env = "ATTEST_OIDC_CLIENT_SECRET"
role_claim = "groups"
allowed_domains = ["example.com"]
[auth.oidc.role_map]
"attest-admins" = "admin"
"security-engineering" = "engineer"

[sources.okta]
type = "okta"
schedule = "0 */4 * * *"
[sources.okta.params]
org_url = "https://example.okta.com"
token_env = "OKTA_TOKEN"

[sources.bamboohr]
type = "bamboohr"
schedule = "30 5 * * *"
[sources.bamboohr.params]
subdomain = "example"
token_env = "BAMBOOHR_TOKEN"

[sources.leavers]
type = "hris-idp-join"
schedule = "0 6 * * *"

[sources.github-org]
type = "github"
schedule = "0 */6 * * *"
[sources.github-org.params]
org = "example"
token_env = "GITHUB_TOKEN"

[[acceptances]]
control = "CTL-VENDOR-01"
owner = "vendors@example.com"
reason = "BAA execution in progress; tracked in VEND-118"
expires = "2026-10-31"

[notifications]
slack_enabled = true
notify_on = ["FAIL", "finding"]
due_days = 14
[notifications.owners]
CTL-ACCESS-02 = "iam@example.com"
[notifications.jira]
base_url = "https://example.atlassian.net"
project = "SEC"
email = "attest@example.com"
token_env = "JIRA_TOKEN"

[security]
login_rate_per_minute = 10
api_rate_per_minute = 600
hsts = true
audit_worm_bucket = "s3://compliance-worm/attest"
audit_worm_retain_days = 2555
```
